# seKUrity Bot

Discord.js + TypeScript 기반 보안/운영 보조 봇입니다.

## Setup

```bash
npm install
cp .env.example .env
```

`.env`에 값을 채운 뒤 Discord Developer Portal에서 **Message Content Intent**를 켜야 메시지 수정 전/후 내용을 기록할 수 있습니다.
Bot은 PostgreSQL에 직접 접근하지 않고 Fastify Backend의 내부 API를
사용합니다. `BACKEND_API_URL`과 `BACKEND_API_TOKEN`을 설정해야 합니다.

개발 서버에는 Guild command를 등록한 뒤 Bot을 실행합니다.

```bash
npm run deploy:commands:guild
npm run dev
```

Global command 전환은 Global 등록을 먼저 확인한 후 Guild command를
삭제하는 순서로 진행합니다.

```bash
npm run deploy:commands:global
npm run delete:commands:guild
```

`deploy:commands`는 기존 실행 환경을 위해 `deploy:commands:guild`의 별칭으로
유지됩니다.

운영 실행은 빌드 후 시작합니다.

```bash
npm run build
npm start
```

## Commands

`/setchannel type: logs`

현재 채널을 메시지 수정 로그 채널로 지정합니다.

`/setchannel type: logs channel: #channel`

선택한 채널을 메시지 수정 로그 채널로 지정합니다.

`/setchannel type: scrums channel: #forum`

선택한 포럼 채널을 스크럼 게시물이 생성될 채널로 지정합니다.
설정할 때 프로젝트·스터디·개인 스터디·개인 활동 분류 태그와 안내 태그가 자동으로
준비되며, `스크럼 만들기` 버튼이 포함된 작성 방법 게시물이 생성·고정됩니다.
작성한 스크럼이 매주 주간보고에 반영된다는 안내도 함께 표시됩니다.
봇에는 채널 보기, 채널 관리, 스레드 관리, 메시지 전송, 스레드 메시지
전송, 파일 첨부, 메시지 기록 보기, 링크 임베드, 메시지 고정 권한이
필요합니다.

`/setchannel type: approve channel: #forum`

새 스크럼 승인 요청이 생성될 포럼 채널을 지정합니다. 이 포럼에도
스크럼 분류 태그가 자동으로 준비됩니다.

`/setapprover role: @role`

여러 역할에 스크럼 승인·반려 권한을 부여할 수 있습니다.
`/unsetapprover`로 해제하고 `/listapprovers`로 현재 목록을 확인합니다.
`Administrator` 권한 보유자는 설정된 역할이 없어도 항상 처리할 수 있습니다.

`/setchannel type: weekly channel: #forum role: @role`

선택한 역할의 사용자마다 주간보고 포럼 게시물을 준비합니다. 안내 임베드에는
주차 마감과 스크럼 자동 동기화 규칙이 Markdown으로 표시되며, 별도로
완료한 작업을 기록하는 버튼이 포함됩니다.

`/syncweekly`

`서버 관리` 권한이 있는 운영자가 삭제되거나 누락된 사용자별 주간보고
게시물을 다시 생성합니다. 주차 마감 전에 실행하면 이미 작성된 이번 주 보고서도
복구된 게시물에 다시 연결합니다. 전체 서버 멤버 조회는 길드별로 한 번만
수행하고 이후 역할 변경 이벤트가 반영된 캐시를 재사용합니다.

`/newscrum`

모든 서버 구성원이 사용할 수 있습니다. 단계별 입력에서 스크럼 구분
(프로젝트·스터디·개인 스터디·개인 활동), 스크럼 제목, 개요와 첫 진행할 작업을
입력합니다. 첫 진행할 작업 모달에는 현재 주차의 일요일 날짜가 표시됩니다.
일요일에 생성하면 당일이 표시됩니다.
첫 모달에는 제출 파일 입력이 표시되지 않습니다. 프로젝트 또는 개인 스터디를
선택하면 다음 Ephemeral 메시지의 버튼으로 전용 모달을 엽니다. 프로젝트는
24MB 이하의 기획서 PDF와 PROJECT:SCORE 결과 Markdown 파일을 각각 1개씩
첨부해야 하며, 개인 스터디는 24MB 이하의 기획서 PDF 1개를 첨부해야 합니다.
스터디와 개인 활동은 이 단계를 건너뜁니다.

제출 직후에는 실제 스크럼을 만들지 않고 승인 포럼에 요청 게시물을
임베드 형식으로 생성합니다. 승인자가 버튼으로 승인하면 스크럼 포럼 게시물과 PostgreSQL의
활성 스크럼이 생성됩니다. 게시물 이름은 `[요청자 이름] 스크럼 제목`이며,
분류 태그와 안내 임베드, 스크럼 완료 버튼이 함께 표시됩니다. 승인 결과는
신청자에게 임베드 DM으로 전송됩니다. 반려 시에는 사유를 필수로 입력하며,
사유는 DB에 저장되고 신청자에게 반려 임베드 DM으로 전송됩니다.
`스크럼 - 시작` 메시지의 `첫 진행할 작업 수정` 버튼으로 첫 기록을 작성하기
전까지 시작 작업 목록을 수정할 수 있습니다.

스크럼 참여자는 게시물의 완료 버튼으로 스크럼을 종료할 수 있습니다.
완료 버튼을 누르면 Ephemeral 메시지에서 전체 진행할 작업을 계속 확인하며,
현재 기록할 작업만 화살표와 굵은 글씨로 강조됩니다.
이후 현재 진행할 작업마다 증빙 파일 또는 링크를 차례로 입력합니다. 제출이 끝나면
작업별 Markdown 상세 기록과 첨부 파일을 먼저 추가하고, 마지막에 완료 임베드를
전송한 뒤 완료 버튼을 비활성화합니다.

`/scrum`

어느 날이든 현재 주차에 사용할 수 있습니다. 주간보고와 동일하게 KST 화요일
19:00에 주차가 전환됩니다. Discord에는 각 주차를 화요일 19:00 마감으로
표시하며, 내부적으로는 주간보고 연결을 위한 일요일 주차 키를 유지합니다. 명령어 또는 작업
임베드의 `다음 스크럼 작성하기` 버튼으로 시작할 수 있습니다. Ephemeral
메시지에서 전체 진행할 작업과 현재 기록할 작업을 확인한 뒤, 작업별 모달로 결과, 증빙 링크 1개
또는 첨부파일 1개, 메모, 추가 완료 작업, 다음 스크럼까지 진행할 작업을
기록합니다. 작업 결과는 증빙 파일·링크·메모 중 하나 이상을 입력해야
제출할 수 있습니다. 제출된 기록은 H2 작업 제목과 인용 메모로 구성한
Markdown 상세 기록 및 첨부 파일을 먼저 전송하고, 요약 임베드를 마지막에
전송합니다. 미완료 작업은 취소선과 `[미완료]`로 표시합니다.

`/weekly`

어느 날이든 현재 주차에 사용할 수 있습니다. 해당 주의 스크럼 완료 작업을 자동 집계하며,
별도로 완료한 작업을 추가할 수 있습니다. 스크럼을
승인·포기·제출하면 주간보고가 자동으로 생성 또는 갱신되고, 스크럼 기록을
삭제하면 연결된 작업도 보고서에서 빠집니다. 완료한 작업과 추가 완료 작업이
모두 없어지면 해당 날짜의 주간보고도 자동으로 삭제됩니다. 보고서 아래의
`추가로 한 작업 작성` 버튼으로 수동 작업을 더할 수 있으며 완료 목록에서는
`[추가]`로 구분됩니다. 작성자는 주간보고 마감인 화요일 19:00 전까지
`주간보고 삭제` 버튼으로 본인의 보고서를 삭제할 수 있습니다. 화요일 19:00이
되면 이전 주차의 주간보고는 수정하거나 삭제할 수 없습니다.

`/weeklyadmin status user: @user`

`서버 관리` 권한이 있는 운영자가 사용자의 주간보고 누락 횟수와 게시물을
확인합니다. `/weeklyadmin status-all`은 현재 주간보고 대상 역할을 가진 모든
사용자의 누락 횟수를 보여줍니다. `/weeklyadmin delete`는 관리할 주간보고
게시물 안에서 실행하며, 작성자가 직접 추가한 작업 하나와 삭제 사유를 받아
작업을 삭제하고 사유를 작성자 DM으로 전송합니다. 삭제 후 완료한 작업이
하나도 남지 않으면 해당 주차의 주간보고도 함께 삭제됩니다.

## Notes

봇이 실행 중일 때 관찰한 메시지는 `data/message-snapshots.json`에 저장됩니다. 봇이 기록하기 전에 작성된 메시지는 Discord 캐시 상태에 따라 수정 전 내용이 없을 수 있습니다.
스크럼과 채널 설정 데이터는 Backend를 통해 PostgreSQL에 저장됩니다.
설정된 채널이 삭제되면 Bot이 삭제 이벤트 또는 다음 시작 시점에 이를 확인해
해당 채널 설정을 PostgreSQL에서 제거합니다.

Discord 컴포넌트 제한 검사는 아래 명령으로 실행할 수 있습니다.

```bash
npm run check:components
```

평일 주간보고 전체 흐름 테스트는 루트의
`docker-compose.weekly-test.yml`을 사용합니다. 별도 테스트 봇과 PostgreSQL
볼륨을 사용하며 자세한 실행 순서는 루트 `README.md`의
`Weekly Report Test Date` 항목에 있습니다.

## Test Scrum

실제 스크럼 포럼 게시물과 PostgreSQL 데이터를 생성하는 테스트 스크립트입니다.
`next_scrum_date`는 실행 당일로 설정되며, 테스트 사용자는 기본적으로 서버 소유자입니다.
스크럼 작성 UX를 바로 검증하기 위한 도구이므로 승인 요청 단계는 의도적으로
건너뜁니다.

```bash
npm run test:newscrum
```

특정 서버 구성원을 테스트 참여자로 지정하려면 Discord 사용자 ID를 전달합니다.

```bash
npm run test:newscrum -- 123456789012345678
```
